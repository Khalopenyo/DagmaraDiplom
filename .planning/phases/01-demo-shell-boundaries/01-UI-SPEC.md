## Layout Contract

- Use one persistent `AppShell` with three regions: left sidebar, top header, and routed main content.
- Sidebar width is fixed at `264px`; it stays visible across all Phase 1 routes.
- Header height is `80px`; it spans the content column and stays visually consistent on every route.
- Main content is centered with `max-width: 1200px`, `32px` horizontal padding, `32px` top padding, and `48px` bottom padding.
- To preserve mobile proportions, place page intros and placeholder cards inside a primary narrative column with `max-width: 760px` within the larger page container.
- Default card padding is `24px`; use `32px` only for the first-screen intro card on `Главная`.

## Visual Hierarchy Contract

- On `Главная`, the accent-tinted intro card is the first visual anchor, the route title is the second anchor, and the primary CTA is the third anchor.
- The sidebar provides orientation, not dominance: active-route treatment must be visible but visually subordinate to the main intro card.
- Placeholder cards on secondary routes should never outshine the route title or the simulation boundary copy.

## Primitive Inventory

|-----------|----------|
| `AppShell` | Persistent wrapper that owns sidebar, header, and route outlet. Shell must not remount during route changes. |
| `SidebarNav` | White surface with `24px` padding. Contains logo/product block, four top-level routes only, and enough bottom breathing room that `Настройки` does not feel detached. |
| `SidebarNavItem` | Height `48px`, `16px` horizontal padding, `12px` icon-to-label gap, `16px` corner radius. Active item uses accent-tinted background plus a `3px` accent rail. |
| `TopHeader` | White surface with subtle bottom border. Left: greeting `Здравствуйте, Дагмара`. Center/right: faux-search. Far right: notifications button. |

| `NotificationButton` | Icon-only control at `44px` square. Must include `aria-label="Уведомления"` and a tooltip or text alternative `Уведомления`. Show hover and focus states only. No dropdown, unread list, or numeric badge in Phase 1. |
| `PageContainer` | Constrains top-level page title, disclaimer, and card stack to the centered content column. |
| `ShellCard` | White surface, `24px` radius, `1px` soft border, optional soft shadow, `24px` padding, vertical stack with `16px` internal gap. |
| `StatusBadge` | Pill height `32px`, `12px` horizontal padding, accent tint background, semibold `14px` text. The shell-level badge label is exactly `Simulated demo`. |

## Icon Contract

- Use outline icons only, sized `20px` inside controls and `18px` inside nav items.
- Stroke weight is `1.75`.
- Rounded line caps and joins only.
- Do not use filled banking pictograms or skeuomorphic finance illustrations in Phase 1.

---

## Navigation And Interaction

- Root route `/` redirects to `/dashboard` or the route labeled `Главная`; this is the canonical landing view.
- Top-level navigation is route-based SPA navigation only. Route switches must not trigger a full browser reload.
- Hover transitions use `160ms ease-out`; route content entry may use a subtle `200ms` fade and `8px` upward settle, but no heavy page choreography.
- Focus-visible state is a `2px` accent ring with `2px` offset on nav items, search, buttons, and interactive cards.
- Search and notifications are display-first shell elements. They can be focused and visually activated, but they must not imply backend search, inbox syncing, or live notification delivery.
- Unknown routes render the shared error-state card with the Phase 1 error copy and a single CTA: `Вернуться на главную`.

---

## Simulation Framing Contract

- A persistent `Simulated demo` badge must remain visible on every top-level route.
- Every Phase 1 route begins with the same short boundary line: `Клиентская симуляция с фиктивными данными. Реального движения денег и официальных интеграций с центральными банками нет.`
- `Главная` and `Переводы` use an accent-tinted intro card for the boundary line because they frame the main scripted flow.
- `Обмен валют` and `Настройки` use the same boundary copy as inline helper text above the first placeholder card.
- Never use language that implies live balances, real settlement, official central-bank connectivity, or production-grade security.
