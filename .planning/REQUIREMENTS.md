# Requirements: MVP веб-платформы для трансграничных переводов в цифровых валютах ЦБ

**Defined:** 2026-04-08
**Core Value:** Пользователь должен за один непрерывный сценарий понять, как цифровой рубль конвертируется в цифровую валюту другой страны и как эта транзакция прозрачно отслеживается между центральными банками.

## v1 Requirements

### Navigation

- [ ] **NAVG-01**: Пользователь видит desktop-layout с левой боковой навигацией, содержащей разделы «Главная», «Переводы», «Обмен валют» и «Настройки».
- [ ] **NAVG-02**: Пользователь видит верхнюю панель с приветствием «Здравствуйте, Дагмара», глобальным поиском и уведомлениями.
- [ ] **NAVG-03**: Пользователь может переходить между основными разделами без перезагрузки браузера.
- [ ] **NAVG-04**: Пользователь видит основной контент по центру экрана с ограничением ширины до `1200px`.

### Dashboard

- [x] **DASH-01**: Пользователь видит виджет цифрового счета с именем владельца, маскированным номером `4756 •••• •••• 9018` и балансом по умолчанию `3 469.52 ЦР`.
- [x] **DASH-02**: Пользователь видит панель быстрых действий с пунктами «Аккаунт и счета», «Переводы», «Снятие», «Оплата счета», «Накопления», «Кредитная карта», «Отчет о транзакциях» и «Контакты».
- [x] **DASH-03**: Пользователь может начать сценарий перевода из дашборда через навигацию или быстрое действие «Переводы».

### Rates Directory

- [x] **RATE-01**: Пользователь видит справочник цифровых валют дружественных стран с флагом и названием страны для каждой строки.
- [x] **RATE-02**: Пользователь видит для каждой строки базовое значение `1 ЦР` и курс целевой цифровой валюты.
- [x] **RATE-03**: Пользователь видит как минимум курсы для Китая, Вьетнама и Южной Кореи, помеченные как симулированные данные.

### Transfer Flow

- [x] **XFER-01**: Пользователь может выбрать счет списания и видит доступный остаток перед отправкой перевода.
- [x] **XFER-02**: Пользователь может выбрать тип перевода: по номеру карты или по номеру телефона.
- [x] **XFER-03**: Пользователь может выбрать избранного получателя из карусели с предзаполненными контактами или начать добавление нового.
- [x] **XFER-04**: Пользователь может вручную ввести идентификатор получателя в формате, соответствующем выбранному типу перевода.
- [x] **XFER-05**: Пользователь может указать сумму списания, после чего сумма получения автоматически пересчитывается по выбранному курсу.
- [x] **XFER-06**: Пользователь видит до подтверждения курс конвертации, сумму списания, сумму получения, комиссию платформы и итог.
- [x] **XFER-07**: Пользователь не может подтвердить перевод, если обязательные поля не заполнены или сумма превышает доступный остаток.
- [ ] **XFER-08**: Пользователь может подтвердить перевод и запустить симуляцию обработки транзакции.

### Transaction Tracking

- [ ] **TRCK-01**: После подтверждения пользователь видит уникальный номер транзакции или смарт-контракта.
- [ ] **TRCK-02**: Пользователь видит пошаговый статус-бар, отражающий маршрут через ЦБ РФ, центральный банк страны-получателя и зачисление средств получателю.
- [ ] **TRCK-03**: Пользователь видит детерминированное продвижение транзакции по шагам с явным указанием текущего статуса.
- [ ] **TRCK-04**: Пользователь видит электронный чек с отправителем, получателем, номером телефона, суммой перевода, комиссией платформы и итоговой суммой.
- [ ] **TRCK-05**: Пользователь видит в чеке те же финансовые значения, которые были подтверждены на шаге отправки перевода.

### Demo Boundaries

- [ ] **DEMO-01**: Пользователь видит на ключевых экранах, что платформа является симулированным demo-прототипом с фиктивными данными.
- [ ] **DEMO-02**: После завершения сценария пользователь может перезапустить демо и вернуться в исходное состояние для повторного показа.

### Settings

- [ ] **SETT-01**: Пользователь может открыть раздел «Настройки» и увидеть краткую информацию о границах демо, сценарии использования и симуляции данных.

## v2 Requirements

### Demo Enhancements

- **ENHN-01**: Пользователь может переключаться между несколькими преднастроенными трансграничными коридорами в самом сценарии перевода.
- **ENHN-02**: Пользователь может включить guided explanation mode с пояснениями по каждому этапу перевода.
- **ENHN-03**: Пользователь видит визуализацию corridor rail между участниками перевода.

### Research Extensions

- **RSCH-01**: Пользователь видит сценарий выбора лучшего курса или bridge-currency для конвертации.
- **RSCH-02**: Пользователь может сравнить CBDC-перевод с традиционным трансграничным переводом в отдельном сравнительном блоке.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Реальный backend, API и база данных | MVP должен оставаться frontend-only и воспроизводимым на защите диплома |
| Реальные интеграции с ЦВЦБ, смарт-контрактами и банковскими шлюзами | В рамках прототипа нужна только клиентская симуляция процессов |
| Аутентификация, KYC, AML и управление пользователями | Эти функции не поддерживают основной демо-сценарий и резко увеличивают scope |
| Административная или комплаенс-панель | Это второй продукт, который не нужен для демонстрации пользовательского пути |
| Полноценная история операций, аналитика и экспорт отчетов | Для MVP важен один убедительный сценарий, а не back-office функциональность |
| Нативное мобильное приложение | Текущая задача ограничена desktop web-адаптацией существующего mobile UI |
| Live-курсы валют и сетевые зависимости | Демо должно быть стабильным, предсказуемым и независимым от внешних сервисов |
